### Design and UX recommendations
1. In [`calibrate.tsx`](file:///C:/Coding/GitHub-GalexY727/Hackathons/baymax/dashboard/web/src/calibrate.tsx#L177-L193) on mobile viewports (e.g. 390 px width), `.servo-table` is wrapped in `.servo-scroll` with `min-width: 900px`. While horizontally scrollable, there is no visual cue (such as a scroll shadow, fade indicator, or "scroll horizontally to edit limits" hint) to indicate that editable inputs for Min, Max, Offset, Speed cap, and Jog lie to the right outside the screen edge. Adding a subtle horizontal scroll indicator and sticky first column (`Servo` name) will improve mobile usability.
2. In [`record.tsx`](file:///C:/Coding/GitHub-GalexY727/Hackathons/baymax/dashboard/web/src/record.tsx#L170-L190), trimming relies solely on dual-handle range sliders. Adding numeric stepping buttons (+/- 0.1 s) or direct text inputs alongside the sliders would allow therapists and operators to trim start and end keyframes with exact frame-level precision on touchscreens.
3. In [`library.tsx`](file:///C:/Coding/GitHub-GalexY727/Hackathons/baymax/dashboard/web/src/library.tsx#L160-L200), hover preview works seamlessly on desktop, but mobile touch devices lack hover states. Tapping a card on mobile immediately opens the play confirm dialog. Adding an explicit "Preview" button or tap-to-preview mode on mobile cards would allow touchscreen users to preview animations without triggering the play confirmation flow.
4. In [`sessions.tsx`](file:///C:/Coding/GitHub-GalexY727/Hackathons/baymax/dashboard/web/src/sessions.tsx#L370-L410), the "Replay on the twin" control opens the 3D twin next to the primary joint angle chart, scrubbing the currently selected set. For multi-set workouts, adding an explicit set indicator badge directly above the replay controls would clarify which set is being demonstrated as the user toggles between sets.
